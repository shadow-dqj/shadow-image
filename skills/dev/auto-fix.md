# auto-fix

## 描述

根据编译错误、测试失败或代码审查反馈，自动修复代码。

## 触发条件

- "修复编译错误 / fix build errors"
- "修复测试 / fix tests"
- "根据错误信息修复 / auto fix"
- build-verify 返回错误后

## 上下文依赖

- build-verify 的错误输出
- 测试失败报告
- 源文件内容

## 修复策略

### 编译错误修复优先级

1. **类型不匹配** → 修正类型声明或转换
2. **未定义的标识符** → 补 import / 检查拼写 / 生成缺失定义
3. **缺少依赖** → 先报告缺失依赖和推荐安装命令；不要自动执行 `npm install`、`go get` 或修改 lockfile，除非用户明确确认
4. **语法错误** → 修正语法

### 测试失败修复

1. **断言条件错误** → 修正期望值
2. **Mock 期望不匹配** → 调整 mock 参数
3. **空指针/panic** → 补充 nil 检查
4. **并发竞态** → 加锁或使用 channel

### 修复规则

- 每次只修复一类错误
- 修复后重新运行 build-verify 验证
- 最多重试 3 次，超过则报告人工介入
- 修复结果必须再次通过所有验证

## 修复流程

```text
build-verify 错误
    ↓
分类错误（compile / test / lint）
    ↓
逐个修复（每次修复后重新编译）
    ↓
全部通过 → 报告修复摘要
还有失败 → 重试（最多3轮）
超过3轮 → 列出未修复项，请求人工介入
```

## 安全约束

- 不修改数据库迁移文件（已执行的）
- 不修改配置文件
- 不修改 `go.mod` / `go.sum` / `package.json` / lockfile，除非用户明确确认依赖变更
- 修复范围限制在生成/修改的文件内
